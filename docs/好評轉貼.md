## 1. 現況

- 好評分享（`/share`）只有一種格式「心得文章」：標題、分享人、機種、聽力狀況、摘要、封面圖、內文。
  要勾「已取得當事人同意」才能發佈；後台和官網兩邊都會擋。
- 目前只有 2 則範例草稿，沒有公開的內容。
- 後台提示寫著「請勿張貼別家業者或網路上的評價」。轉貼自己門市的評論要改成只禁止別家業者的評價。

## 2. 取得 Google 評論的三種方式

| 方式 | 拿得到什麼 | 能不能長期放在官網 | 結論 |
|---|---|---|---|
| Places API（地點詳細資料） | 最多 5 則，由 Google 挑選，不能指定 | **不行**：條款不准儲存評論內容，要即時抓，而且要標 Google 的出處 | 不用 |
| Google 商家檔案 API（Business Profile API） | 自己店的全部評論、星等、時間、店家回覆；也能用 API 回覆評論 | **不行**：條款規定 API 的內容最多暫存 30 天，不准建索引或長期儲存 | 只適合當「評論收件匣」（第 4 節第二步），不能當轉貼來源 |
| 店員手動轉貼（徵得本人同意） | 店員挑的任何一則 | **可以**：文字是評論者自己寫的，經本人同意轉貼，就不是從 Google 搬資料 | **第一步就用這個** |

- Google 地圖的使用條款不准複製地圖上的內容，也不准大量下載；
  評論的著作權屬於寫的人。所以轉貼的根據是**評論者本人同意**，不是「評論是公開的」。
  這也和現有規則「好評要本人同意才發佈」一致。
- 每則評論都可以拿到官方的單則連結：在 Google 地圖打開那則評論 → 「更多」→「分享評論」→「複製連結」。
  官網附這個連結，讓人可以看原文。

## 3. 資料格式（同一張表，多一種格式）

`extra.format`：`story`＝心得文章（現有的；沒有這個欄位的舊資料都算這種），`quote`＝評論轉貼（新增）。

評論轉貼的欄位：

| 欄位 | 說明 |
|---|---|
| `extra.source.platform` | 平台代碼，見下方平台清單 |
| `extra.source.url` | 原文連結；網域要符合該平台，例如 Google 只接受 `maps.app.goo.gl`、`google.com/maps`、`g.co`。門市心得卡可以不填 |
| `extra.source.rating` | 星等 1–5；平台沒有星等的話不填 |
| `extra.source.posted` | 評論日期，填到「月」就可以。Google 只顯示「3 週前」這種相對時間 |
| `extra.original` | 原文，照貼不改（官網不顯示，用來檢查節錄） |
| `body_md` | 官網顯示的文字：等於原文，或是原文的節錄 |
| `extra.person` | 官網顯示的稱呼，照本人同意的寫法，例如「王小姐」；預設不寫全名 |
| `extra.consent`、`consent_how`、`consent_date` | 同意與否、方式（當面／LINE／電話／書面）、日期；店員帳號自動記在 `updated_by` |
| `title` | 只給後台列表看，自動產生，例如「Google｜王小姐｜2026-10」 |

**平台清單**：和其他共用清單一樣，`y1crm api/web_admin.py` 與 `y1web app/content.py` 各存一份，要一起改。
以後要加平台，兩份清單各加一行就好：

```python
SHARE_PLATFORMS = {   # 代碼: (顯示名稱, 原文連結允許的網域, 有沒有星等)
    "google":   ("Google 地圖評論", ("maps.app.goo.gl", "google.com", "g.co", "goo.gl"), True),
    "facebook": ("Facebook 評論",   ("facebook.com", "fb.com", "fb.me"), False),
    "store":    ("門市心得卡",       (), False),           # 紙本或當面的心得，沒有連結，可以附照片
    "other":    ("其他",            None, False),          # None＝任何 https 網址都可以
}
```

Facebook 粉專的評論只有「推薦／不推薦」，沒有星等。
Instagram、YouTube、Dcard、PTT 這類平台需要時再加。官網只放文字和連結，**不嵌入**各平台的外掛：
網站的 CSP 只允許同源，嵌入也會帶進對方的追蹤 Cookie，和隱私權政策的承諾不符。

## 4. 做法

### 第一步：手動轉貼（不用申請，馬上能做）

**後台**：y1crm 官網管理 → 好評分享 → 新增時選「評論轉貼」或「心得文章」。
評論轉貼的表單依序填：平台、原文連結、星等、評論日期、貼上原文、官網顯示（原文或節錄）、稱呼、同意方式與日期。

**搬一則評論的流程**（2026-11-03 補充，目標是一則 1 分鐘內）：
1. **複製**：用電腦打開 Google 地圖的門市頁或商家檔案 →「評論」，排序選「最新」。
   從評論者的名字一路選到評論最後一個字，按 Ctrl+C。長評論要先按「更多」展開。
2. **貼上**：貼到 CRM 的「貼上整段評論」框，程式會自動拆出名字、日期和內文。
   - 會略過「52 則評論」「讚」「分享」這些介面上的字。
   - 「3 週前」這類相對時間會換成大約的年月。
   - 「業主回應」之後的字會分開放，不算評論內容。
   - 星星是圖片，複製不到，預設 5 顆，不對再點。
   - 拆錯可以直接改欄位。拆解規則照 Google 目前的版面寫，第一次要用實際複製的內容調整。
3. **連結**（選填）：在那則評論按「分享評論」→「複製連結」，貼到原文連結欄。
4. **程式自動做的**：
   - 用名字建議稱呼，例如「王小明」→「王先生／王小姐」，讓店員選；
   - 價格句子標紅，療效或誇大句子標黃，並建議刪掉那幾句的節錄；
   - 同一段原文轉貼過（原文雜湊相同）就警告；
   - 用本機 AI 擬一則回覆，讓店員貼回 Google 回覆評論。回覆不提對方的聽力狀況、不提價格；評論內容不送雲端。
5. **找客人**（選填）：在 CRM 搜尋客戶，把這則評論掛到客戶資料上，方便取得同意。
6. **取得同意**：見第 5 節的同意連結。

手機版：Google 地圖 app 的評論不能選取文字。真的要用手機，可以截圖上傳，交給本機的 qwen3-vl（好卡 0002）辨識文字。
一張大約 1 分多鐘，那張卡也有別的程式在用，所以先不做；電腦複製貼上比較快也比較準。

存檔時檢查：
- **節錄只能刪，不能改寫**：每一段都要在原文裡找得到、順序相同，中間用「……」接；
  不符合就不能存。不准改寫是因為評論掛著別人的名字。
- **價格不能發佈**：沿用粉專貼文的文字檢查 `fb_page.check_post_text`。
  評論常有「價格實在」這類字，要用節錄刪掉。
- **療效或誇大用語會提醒**：例如「聽得超清楚」「最專業」，也是同一套檢查；店員確認後才能發佈。
  助聽器是醫療器材，見證效果的內容風險高，建議節錄服務的部分（解說、耐心、調整、到府）。
- 原文連結的網域要符合平台；沒勾同意就不能發佈，這條沿用現有規則。

**官網 `/share`**：
- 上面一區「客人怎麼說」：評論卡片，內容是星等、文字、稱呼、年月、平台名稱，以及「看原文」連結
  （另開視窗，`rel="nofollow noopener"`）。長評論先收合，用 `<details>` 展開，不需要 JS。
- 下面一區「使用心得」：現有的心得文章卡片。
- 頁尾一行：「精選自 Google 地圖等平台的評論，經本人同意轉貼，文字未修改（節錄處以……標示）。」
  另外放「到 Google 地圖看全部評論」連結，需要門市在 Google 地圖上的地點連結。
- 首頁的好評區兩種格式混著排，取最新 3 則。
- 評論轉貼**沒有自己的網頁**（內容短，獨立成頁沒有意義），也不進網站地圖。

**不做**：
- 不複製評論者的大頭照，改用平台圖示。
- 不加 schema.org 的 Review／AggregateRating 標記：Google 不讓店家在自己的網站標記自己的評論，
  標了也不會顯示星星，還可能被當成違規。
- 不顯示「Google 4.9 顆星」這種總分：手動填的數字很快就過時。

**隱私權政策**：新增「好評分享」一段，說明會經本人同意轉貼評論並附原文連結，想撤下時要怎麼聯絡，以及多久內下架。

#### 圖片與彈窗（John 2026-11-07）

John：「好評分享提供單張圖片變更尺寸縮圖顯示，無圖片預設為分享平台 LOGO。點擊後彈出內嵌開啟原文連結網頁顯示。」
同日第二輪：「彈出的視窗內容請置中滿版，想個辦法讓原始連結嵌進。圖片縮圖不美觀也不清楚，做成背景或什麼方式。」

- **存法**：沿用 `web_posts.cover`（只存檔名，資料庫不加欄位）。上傳封面時 y1crm 照舊轉 WebP、縮到 1600px（彈窗大圖），
  另外做一張卡片圖放 `media/uploads/c/同檔名`（剛好蓋滿 720×480、品質 78，照片約 50–70 KB）。
  檔名是內容雜湊，同一張圖只存一份；刪圖時兩張一起刪。沒有卡片圖的舊圖官網用原圖（`content.thumb_url`）。
  （第一輪的 64px 方塊縮圖放在 `t/`，第二輪改掉、資料夾已刪。）
- **卡片**：有圖＝卡片上方滿版、裁成 3:2；沒圖＝平台標誌放在右下角當淡淡的背景（Google＝`google-g.svg`、
  Facebook＝`facebook.svg`、門市心得卡＝`logo-mark.svg`、其他＝`quote.svg`）。標題列「標誌＋平台名稱＋星等」。
- **彈窗**（`_share_dialog.html`＋`site.js`）：全螢幕，上方標題列＋關閉鈕，下面左「原文」右文字，整組置中；手機上下排。
  點卡片任何地方（含「看原文」「看全文」）開；Esc、關閉鈕、手機返回鍵都能關。沒有 JS 時「看原文」照常開原文網頁。
  用 `dialog.show()`＋蓋滿畫面＋焦點拉回，不用 `showModal()`：測試時 Facebook 嵌入貼文在 modal 裡一直沒顯示。
- **原文嵌入**（2026-11-07 用 curl 查過）：
  - Google 地圖的評論頁、地點頁、`maps.app.goo.gl`、`search.google.com/local/reviews`、`g.page` 全部回
    `X-Frame-Options: SAMEORIGIN`，瀏覽器不准別的網站嵌入，沒有合法的繞法（伺服器代抓或截圖都違反 Google 條款）。
    → 彈窗左邊嵌**門市的 Google 官方嵌入地圖**（位置＋Google 上即時的總評分與評論數）；有圖片時圖片在左、地圖在右下。
    「開啟 Google 地圖原文」在電腦上開一個置中的小視窗（`window.open` popup），手機照連結開（新分頁／Google 地圖 App）。
  - Facebook：官方「嵌入貼文」`facebook.com/plugins/post.php?href=…` 可以放進 iframe（測過），貼文要是公開的。
    彈窗左邊直接顯示原文貼文，下方仍有「到 Facebook 看原文」按鈕（嵌入失敗時用）。y1crm 提示店員貼貼文的永久網址
    （點貼文時間 → 複製網址）。無頭瀏覽器截圖時 Facebook 嵌入時有時無，真瀏覽器還沒驗。
  - 嵌入的內容點開才載入、關掉就移除；iframe 加 sandbox。
- **地圖網址**：預設用門市名稱搜尋（`/maps?output=embed&hl=zh-TW&q=門市名稱`，測過會找到「睿聲助聽器-中正門市」）；
  要指定的話在 y1crm「看全部評論」連結的「修改」貼 Google 地圖「分享 → 嵌入地圖 → 複製 HTML」（存在 web_settings
  share_links 的 `map`，只收 `https://www.google.com/maps/embed?pb=…`）。
- **CSP**：`frame-src https://www.google.com/maps https://www.google.com/maps/embed https://www.facebook.com/plugins/post.php`。
- **隱私權政策** #share 補一句：點開 Google 地圖或 Facebook 評論時，地圖、貼文由它們提供，沒點開就不會連過去。

### 第二步：Google 評論收件匣（之後再做）

條件：門市擁有或管理 Google 商家檔案、商家檔案已驗證、Google 核准 Business Profile API 的使用權（要另外申請）。

- y1crm 每天抓一次新評論，只存 30 天（API 條款），列在「評論收件匣」，並通知店員有新評論。
- 本機 AI 擬回覆（評論內容不送雲端），店員確認後才用 API 回覆到 Google 上。
  API 條款也規定回覆要有店家授權。
- 「轉貼到好評分享」按鈕：把星等、日期、連結帶進第一步的表單；原文仍然由店員照貼。
  照樣要取得本人同意才能發佈。
- 已經轉貼的評論如果在 Google 上被刪掉或修改，收件匣會提醒店員下架或更新。

## 5. 怎麼取得同意

> **John 2026-11-04：同意連結不做。** 店員當面、電話或 LINE 手動問過，勾「已取得當事人同意」。以下同意連結的設計留作參考。

### 同意連結（沒做）

大部分寫評論的人都是門市的客人，Google 上的名字通常認得出來。

**同意連結**（建議；評論轉貼、心得文章都能用）：
1. 內容檢查好以後，店員按「產生同意連結」，CRM 會附一段可以直接複製的訊息，例如：
   「王小姐您好，謝謝您在 Google 上的評論！我們想把這段話放在官網的好評分享，刊登前想先問您。點這裡可以看刊登的樣子：https://y1ear.com/share/ok/…」
2. 店員用 LINE 官方帳號或 Messenger 手動傳給客人；在店裡的話，請客人用手機掃螢幕上的 QR。
   要從 CRM 直接發 LINE，要 John 另外同意。
3. 客人打開的頁面：
   - 會看到**和官網完全一樣**的卡片；
   - 可以選稱呼：王小姐、王先生、自訂，或不具名「中正門市的客人」；
   - 按「同意刊登」或「不要刊登」。
4. 系統記下同意的時間和選的稱呼，同意方式記成「同意連結」。
   - 同意以後自動上線，或由店員再按發佈，由 John 決定。
   - 產生連結後內容就鎖住；要改內容，得重新取得同意。客人同意的版本就是官網刊登的版本。
5. **撤回**：客人用同一個連結隨時可以按「撤回」，官網立刻不顯示，店員會收到通知。

**技術上**：
- 新增 `y1web.share_consents` 表，記錄文章、連結雜湊（連結本身不存）、狀態、稱呼和時間。
- 官網帳號只能讀寫這張表，不能改 `web_posts`。
- 官網顯示好評時，同時要「已同意」，而且沒有撤回。
- 同意頁 noindex、不快取。
- 沒有回覆的連結 30 天後失效。

**其他同意方式**：當面口頭或紙本同意，照現有的勾選欄位，記下方式和日期。

認不出是誰，或聯絡不到的，就不轉貼。官網的「到 Google 地圖看全部評論」連結還是看得到這則評論。

**每週例行**（建議週一，約 10 分鐘）：
- 看 Google 上新的評論，每一則都回覆，好評、負評都要；
- 4–5 星的照第 4 節的流程搬進 CRM，發同意連結；
- CRM 列表顯示每則的狀態：待同意、已上線、不同意、撤回、聯絡不到。
- 注意：Google 不准「只邀請滿意的客人寫評論」，也不准用優惠換評論。
  以後如果做「邀請寫評論」的 QR 或連結，要發給每一位客人。
