# 噪音中聽數字測驗：研究與改版

> 2026-10-23。John：「徹底研究噪音數字測驗，更換生成來源或其他方式。別人可以做到，我們應該可以做的更好。」
> 程式：`static/js/noise-test.js`、`templates/noise_test.html`、`scripts/din_calibrate.py`（校正工具）。設計說明 §16。

## 1. 起因

10-22／23 用 edge-tts 合成數字試聽三次，John：背景聲太大、品質太差、正常人也聽不懂。
查出的問題（前三項已修）：

| # | 問題 | 處理 |
|---|---|---|
| 1 | 雜音只疊 40 層，聽得出別的數字、忽大忽小（起伏 40 dB） | 1000 層，起伏 1.5 dB |
| 2 | 雜音 RMS 0.12，訊噪比 +3 dB 以上削波 | 0.06＋限幅器 |
| 3 | 試聽檔每段各自調最大聲，背景比對話大聲 4.5 dB | 固定背景音量 |
| 4 | 兩耳相同（同相）播放 | 改反相（WHO 做法） |
| 5 | 每個數字沒有音量校正 | 加 `levels.json`＋門市校正工具 |
| 6 | edge-tts 24 kHz 48 kbps MP3、數字只有 0.2–0.4 秒 | 96 kbps、放慢 15%；另評估 Kokoro、Azure／Google |
| 7 | 自訂程序（24 題、一律 2 dB） | 改 hearWHO 程序 |

## 2. 別人怎麼做

- **interton**：`/hearing-test` 是純音測驗（和我們的聽力不求人同類）；`/hearing`「耳力健身房」是**訓練**不是檢測：語音用開源 Kokoro 合成、人聲背景、從數字比背景大 **+18 dB** 開始每級降 2 dB、目標答對約 70%。所以聽起來輕鬆。（只研究做法，不抄文字、程式、音檔。）
- **WHO hearWHO 中文版**（Gu et al. 2025）：女聲真人錄音、**反相**、23 題、120 組三個不同數字、0 dB 開始、前 3 題 4 dB 之後 2 dB、最後 19 題平均。191 人：聽力正常 SRT **−16.9 ± 1.7 dB**（−19.5～−13.6）；切點 **≥ −15.8 dB 可能輕度以上**（敏感度 85.2%、特異度 82.8%）、**≥ −14.2 dB 可能中度以上**（83.5%／81.0%）。
- **反相 vs 同相**（De Sousa et al. 2020）：偵測 > 25 dB HL 的 AUC 0.94 vs 0.77；反相約好 5 dB；和純音平均的相關更高。
- **合成語音可以做**（Polspoel et al. 2025「Aladdin」）：Google Cloud TTS（WaveNet，44.1 kHz WAV）；合成女聲數字 SRT −8.6 vs 真人 −9.4 dB（無顯著差異，同相）；MOS 和真人無差。**每個數字難易差 SD 約 3.2 dB，一定要做音量校正**；用 ASR 自動校正時，雲端 ASR 和人的相關只有 0.54–0.79，HMM 型 FADE 最接近人。完成的 Aladdin 測驗：聽力正常 −11.1（荷）／−12.6（英），敏感度 100%、特異度 84%。
- Fatehifar et al. 2025：TTS＋語音辨識作答的 DIN，可行但再測信度較差（±6 dB）。

## 3. 我們的做法（已改）

- 反相（雜音兩耳同相、數字右耳反相，NoSπ）。**一定要戴耳機**：開始前做耳機檢查（Woods et al. 2017：三個 200 Hz 音選最小聲，6 次對 5 次；用喇叭或「單聲道音訊」時反相音會抵消而答錯）。
- hearWHO 程序：23 題、三個不同數字、0 dB 起、前 3 題答對 −4 dB／答錯 +2 dB、之後 ±2 dB（−26～+10）、最後 19 題平均。正式前 **2 題練習**（+4 dB，不計分，會告訴答案）。模擬 200 次：SRT −17、−9 dB 都估得到（誤差 < 0.6 dB）。
- 數字：前後 5 ms 淡入淡出、RMS 統一，再乘 `static/audio/din/levels.json`（每個數字 ±6 dB 內）。
- 雜音：同一組數字疊 1000 層的穩定雜音，固定 RMS 0.06，數字變大小聲；輸出接限幅器。
- **門市校正模式** `?pilot=1`：結果頁多「門市校正資料」（逐題紀錄），同仁複製交回，資料不上傳。
  `scripts/din_calibrate.py`：每個數字的 SRT（扣掉各人 SRT 後，共同斜率 logistic、猜對率 10%）→ 校正值＝該數字 SRT − 平均；同時算門市常模（平均、標準差）。模擬 40 次測驗，校正值誤差 < 1 dB。

## 4. 聲音來源比較

| 來源 | 腔調 | 音質 | 授權／費用 | 備註 |
|---|---|---|---|---|
| edge-tts（曉臻、曉雨） | 台灣 | 24 kHz MP3，最高 96 kbps | 非微軟正式商用管道 | 0–9 機器聽寫全對；放慢 15% 後數字 0.3–0.5 秒 |
| Azure 語音（同上聲音） | 台灣 | 48 kHz WAV，可用 SSML 調速度 | 要帳號綁卡，免費額度夠 | 正式版建議 |
| Google Cloud TTS（cmn-TW） | 台灣 | 24 kHz WAV（原生 24 kHz，無壓縮） | 要帳號綁卡，0–9 只用幾十字、在免費額度內 | Aladdin 研究用這個。10-23 實測：女聲只有 WaveNet-A、Standard-A，0–9 機器聽寫全對；放慢 15% 後數字 0.53–0.82 秒（試聽頁 F、G）。腳本 `gtts.py`（REST＋只限 TTS 的 API 金鑰）。**John 選 F（WaveNet-A），測驗已改用** |
| Kokoro v1.1-zh | 大陸 | 24 kHz WAV（無壓縮） | Apache-2.0，本機 CPU | 55 個女聲中 31 個 0–9 機器聽寫全對；有些會多念字 |
| BreezyVoice（聯發科） | 台灣 | — | 要 GPU | 主機顯示卡已分配，暫不考慮 |
| 真人錄音 | 台灣 | 最好 | 需同意書 | 傳統做法：專業錄音、挑最好的錄音、聽者校正 |

機器聽者（Whisper small，只用 CPU）在雜音中遠比人差（同相 0 dB 約對 4–8 成、−3 dB 以下幾乎全錯），只能用來排除念錯的聲音，**不能代替人耳選聲音或訂標準**。

## 5. 接下來

1. ~~選聲音~~：10-23 John 選 F＝Google `cmn-TW-Wavenet-A`（速度 0.85），`static/audio/din/0–9.wav` 已換，無頭瀏覽器全流程驗證過。待 John 戴耳機實際做一次測驗，回報背景聲與難度。
2. 聲音已是正式服務產生（Google 原生 24 kHz）。之後若改真人錄音或換聲音、換速度：**校正值與常模都要重做**。
3. 門市校正：約 20 位聽力正常的同仁或家人（最好先做過純音聽檢確認正常），各用 `?pilot=1` 做 2 次 → `din_calibrate.py --write` 寫入校正值 → 再找 10 位做一次，確認常模。
4. 聽力師依門市常模訂 `CUTOFFS`（可參考 hearWHO 中文版 −15.8／−14.2 dB，但不同錄音不能直接套用）。
5. 驗證：同意的客人同時做純音聽檢和本測驗，比對敏感度／特異度後才放進選單。
