| 東西 | 放在哪一份 | 說明 |
|---|---|---|
| 程式 | GitHub `DrHsiao/y1web`（每次 commit）；Drive `code_y1web.tar.zst.gpg`（每晚） | Drive 那份含 Python 環境（venv）和 git 歷史，不含設定檔和圖片 |
| 資料庫 `y1web` | Drive `db_crm.sql.zst.gpg` | 文章、輪播、關於我們、好評、FAQ、門市設定、型錄照設定、按鈕點擊數 |

| systemd 服務單元 | Drive `system.tar.zst.gpg`；程式裡也有 `deploy/y1web.service` | |

- ⚠ `db_crm` 這一份同時有 CRM 的 `crm1`、官網的 `y1web` 和 `y1member`，三個庫的檢視表互相指（`crm1.v_member_fb_points` 讀 `y1web.web_posts`，`y1web.v_catalog` 讀 `crm1.products`），所以必須放在同一份。**主機還正常時不要把整份灌回正式資料庫**，會把 CRM 也一起倒回備份那天（見 §4）。

- 每晚結果：`/var/lib/twdr/status.json`（`"ok": true` 才是成功）；紀錄 `/var/log/twdr/backup_日期.log`。
- 想馬上備一份（例如大改之前）：`systemctl start openclaw-dr-backup.service`（約 25 分鐘，結果同上）。

**不在備份裡的**（換機器時照 §7 重新設定）：Cloudflare 的設定、路由器、.26 的 nginx、Google／LINE／Facebook 開發者後台的設定、健康檢查程式 `/home/john/workspace/health_check.py`。

5. 跑一次測試：`cd /home/john/y1web && ./venv/bin/python -m unittest discover -s tests`。
6. 健康檢查程式沒有備份：在新主機的 `/home/john/workspace/health_check.py`（或新的健康檢查）加回兩行，root 的 crontab 每 5 分鐘跑：

## 4. 主機正常，只救官網的資料

原則：**先把備份還原到一個暫時的資料庫，只把要的那幾筆拿回正式資料庫。** 備份之後店員在官網管理改過的、客人新註冊的會員，整份倒回去就會不見。

### 4.1 下載那一天的備份

```bash
D=2026-11-25                               # 要用哪一天（Drive「災難復原備份/每日/」底下的資料夾名稱）
W=/root/y1web_restore; mkdir -p $W; chmod 700 $W
RC="rclone --config /root/.config/rclone/rclone.conf"
$RC lsf "gdrive:災難復原備份/每日/"         # 看有哪幾天
$RC copy "gdrive:災難復原備份/每日/$D" $W/$D --include MANIFEST.txt --include db_crm.sql.zst.gpg --include files_y1web.tar.zst.gpg
cd $W/$D && grep -E ' (db_crm|files_y1web)\.' MANIFEST.txt | awk '{print $1"  "$3}' | sha256sum -c   # 兩個都要是 OK
```

### 4.2 解密

```bash
P=/root/.config/twbackup/passphrase
gpg --batch --quiet --pinentry-mode loopback --passphrase-file $P -d $W/$D/db_crm.sql.zst.gpg | zstd -dq > $W/db.sql
```

### 4.3 開一個暫時的資料庫，把備份放進去

用 Docker 開一個空的 MySQL 8.0，和正式的資料庫完全分開：

```bash
docker run -d --name y1web-restore -e MYSQL_ALLOW_EMPTY_PASSWORD=1 mysql:8.0
until docker logs y1web-restore 2>&1 | grep -q 'port: 3306'; do sleep 3; done    # 等它開好（約半分鐘）
docker exec -i y1web-restore mysql < $W/db.sql                                     # 約 1 分鐘
docker exec y1web-restore mysql -e "SELECT COUNT(*) FROM y1web.web_posts; SELECT COUNT(*) FROM y1member.members"
```

### 4.4 找到要的資料，放回正式資料庫

先在暫時的資料庫裡找：

```bash
docker exec y1web-restore mysql -e "SELECT id, kind, status, title, updated_at FROM y1web.web_posts WHERE title LIKE '%關鍵字%'"
```

**放回一筆或幾筆**（`--replace`：同一個 id 的那筆會被備份裡的蓋掉；已經刪掉的會重新出現）：

```bash
docker exec y1web-restore mysqldump --no-create-info --replace --skip-triggers y1web web_posts --where="id IN (123,124)" > $W/rows.sql
less $W/rows.sql                                                  # 確認內容
mysql --defaults-file=/etc/mysql/debian.cnf y1web < $W/rows.sql
```

會員資料用同樣的方法，資料庫換成 `y1member`、表換成要救的那張（例如 `member_points`）。

**整個 `y1web` 倒回備份那天**（例如內容被大量改壞）：

```bash
docker exec y1web-restore mysqldump --databases y1web --routines --triggers > $W/y1web.sql
mysql --defaults-file=/etc/mysql/debian.cnf < $W/y1web.sql
```

這會把備份之後在官網管理做的所有修改、按鈕點擊數一起倒回去。`y1member` 不建議整個倒回（備份之後註冊的會員、拿到的點數會不見），只救需要的那幾筆。

官網讀資料有 60 秒快取，放回後最多等 1 分鐘就會出現，不用重啟。

### 4.5 圖片與影片

```bash
F=$W/$D/files_y1web.tar.zst.gpg
gpg --batch --quiet --pinentry-mode loopback --passphrase-file $P -d $F | zstd -dq | tar -tvf - | grep 檔名     # 找
gpg --batch --quiet --pinentry-mode loopback --passphrase-file $P -d $F | zstd -dq | tar -C / -xpf - home/john/y1web/media/uploads/檔名.webp   # 放回一個
gpg --batch --quiet --pinentry-mode loopback --passphrase-file $P -d $F | zstd -dq | tar -C / -xpf -           # 全部放回（備份之後新增的檔案會留著）
```

`media/uploads` 的檔名對應資料庫 `web_posts.cover`；縮圖在 `media/uploads/c/`。

### 4.6 收尾（一定要做）

```bash
docker rm -f y1web-restore
rm -rf $W              # 裡面是解密後的客人與會員資料
```

## 6. 拿不到 Google Drive 備份時：從 GitHub 重建

只拿得回程式。文章、會員、圖片要靠資料庫與圖片的備份，沒有就只剩預設內容。

官網依賴 CRM：預約寫進 `crm1.booking_requests`，產品頁讀 `crm1.products`，會員頁讀 `crm1.customers`。**要先把 y1crm 還原好**，`/home/john/y1crm/config.toml` 要在（`setup_db.py` 用它的管理者帳號建資料庫）。

```bash
# Ubuntu 24.04；先裝好 MySQL 8.0、y1crm
apt-get install -y python3-venv git
git clone git@github.com:DrHsiao/y1web.git /home/john/y1web && cd /home/john/y1web
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
useradd --system --no-create-home -d /nonexistent -s /usr/sbin/nologin y1web
cp config.example.toml config.toml && chown root:y1web config.toml && chmod 640 config.toml
nano config.toml                           # [site] secret 填一長串亂碼；[member] 的 Google／LINE 金鑰從開發者後台重新複製（§7）
./venv/bin/python scripts/setup_db.py      # 建 y1web、y1member、檢視表、資料庫帳號 y1web_app（密碼自動產生寫進 config.toml）
./venv/bin/python scripts/seed_content.py  # 門市設定、FAQ、產品系列的預設內容
./venv/bin/python scripts/sync_images.py   # 型錄照 → media/catalog
cp deploy/y1web.service /etc/systemd/system/ && systemctl daemon-reload && systemctl enable --now y1web
curl -s localhost:8006/healthz
```

⚠ `[site] secret` 能用原本的就用原本的（Drive 的 `secrets` 那一包有）。換了以後：已經打開、還沒送出的預約表單要重新整理；每日聽練在各裝置上記住的會員代號會對不上。會員登入（存在資料庫）和預約碼不受影響。
