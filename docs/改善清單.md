## B. 影響客人上門的問題

### B1　首頁第一眼在推集點活動，不是介紹門市
- **現況**：

  - 從 Google 搜尋來的新客人，看不出這是古亭站附近的助聽器門市。
- **建議**：
  - 第一屏的文字固定不換，放一句話介紹、地址（近古亭站）、電話和預約按鈕。

- **誰來做**：我。介紹文字要你確認。
- **決定**：

### B2　電話不好找
- **現況**：
  - 手機版要捲到最底（大約第 11 個畫面）才看得到電話，而長輩最常用的就是打電話。

## D. 技術問題（我可以直接修）

### D1　大圖的裁切位置設定沒有作用
- **現況**：網站的安全設定（CSP `style-src 'self'`）擋掉了 HTML 裡的 `style="--fx:…"`，每一頁瀏覽器都在報錯。後台設定的焦點位置全部失效，手機上大圖都用預設位置裁切，人物可能被切到。
- **建議**：焦點值改放在 `data-` 屬性，由程式在載入時套用。安全設定維持不變。
- **工作量**：約 30 分鐘，修完逐頁截圖確認。
- **決定**：做（11-25）。
- **✅ 11-25 完成**：後台只有 25／50／70／85 四種位置，所以改用 CSS class（`fx-85` 這種），不用 JavaScript，畫面也不會跳一下。子頁面橫幅在手機上原本也被另一條規則蓋掉，一起修好。手機實測首頁、關於我們、預約頁：照後台的值裁切，瀏覽器不再報錯。

### D2　完全沒有流量統計
- **現況**：Cloudflare 的統計程式也被同一個安全設定擋掉。所以不知道多少人來、從哪裡來、多少人按了預約，也就沒辦法判斷哪個改動有效。
- **建議**：
  - 安全設定放行 Cloudflare Web Analytics（`static.cloudflareinsights.com`）。這套統計不用 cookie。
  - 預約、打電話、LINE 按鈕的點擊另外計數。
  - 隱私權政策補一句有做匿名流量統計。
- **誰來做**：我。需要你確認 Cloudflare 後台的 Web Analytics 是開著的。
- **決定**：做（11-25）。
- **✅ 11-25 完成**：
  - Cloudflare Web Analytics 本來就開著（Cloudflare 自動在頁面插統計程式），只是被擋。放行後實測：統計程式載入、資料送出都成功。到 Cloudflare 後台選 y1ear.com →「Analytics & Logs」→「Web Analytics」看。
  - 打電話、LINE、預約按鈕的點擊數：記在 `y1web.web_clicks`（哪天、哪種、哪一頁、幾次），不記是誰；同一個 IP 一小時最多記 30 次。y1crm「官網管理」最下面多一張「官網按鈕點擊」表：今天、近 7 天、近 30 天，以及在哪一頁按的。
  - 隱私權政策加了「網站使用統計」一段。

### D3　手機首頁太重
- **現況**：手機首頁載入約 1MB，需求清單訂的目標是 300KB。模擬慢速 4G 時，主圖要 3.4 秒才出現（Google 的標準是 2.5 秒內）。主因是手機也在下載 2000px 寬的大圖。
- **建議**：大圖多做手機用的小張版本，用 `srcset` 讓手機自己挑。好評頁的圖片也一起處理。
- **工作量**：約 1 小時，包含舊圖片的批次轉檔。
- **決定**：

### D4　舊備份檔可以從網址直接下載
- **現況**：`static/` 裡有 21 個 `*.bak-*` 檔，都能從網址打開，例如 `/static/js/site.js.bak-20261125-sidepanel`。內容只是舊的樣式和程式，風險不高。
- **建議**：網站一律不提供 `.bak-` 結尾的檔案（回 404）。這樣在原處留備份的習慣不用改。
- **決定**：

### D5　HEAD 請求一律回 405
- **現況**：有些監控和連結檢查工具用 HEAD 方式詢問網站，現在一律被拒絕，會被誤判成網站掛了。
- **建議**：首頁和各頁接受 HEAD 請求。
- **決定**：

### D6　沒有強制 https（HSTS）
- **建議**：在 Cloudflare 後台的 SSL/TLS → Edge Certificates 開 HSTS。也可以由網站自己送這個設定，兩種擇一。
