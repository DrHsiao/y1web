### B. LINE 整合

| 編號 | 功能 | 說明 | 階段 |
|---|---|---|---|
| B1 | 加好友按鈕 | 每頁右下角浮動按鈕，頁尾也有。手機點了直接開 LINE，電腦顯示 QR Code | P1 |
| B2 | 預約後接 LINE | 預約完成頁有「加 LINE 收提醒」按鈕：開啟 LINE 並自動帶入預約碼，客人按傳送後，機器人就把這筆預約和他的 LINE 連起來，回覆確認（用免費的 reply）。前一天提醒沿用現有排程，不用另外寫 | P1 |
| B3 | 活動同步 | 官網「最新活動」就是 LINE 圖文選單「最新活動」的內容來源，附「看完整內容」連結 | P1 |
| B4 | 常見問題同步 | 同一份 FAQ 同時用在官網、LINE 常見問題按鈕、AI 客服知識庫。**價格相關欄位不給 AI**，延續現在 AI 不談價格的規定 | P2 |
| B5 | 門市資訊同步 | 地址、電話、營業時間只維護一份，官網、LINE、AI 都讀它 | P2 |

| B7 | 從官網來的好友 | 加好友連結帶來源參數，用來統計有多少好友是從官網來的 | P2 |

### C. 預約與 y1crm 串接

| 編號 | 功能 | 說明 | 階段 |
|---|---|---|---|
| C1 | 官網預約寫入 y1crm | 寫進現有 `booking_requests`，標記「來源：官網」，和 LINE 預約一起出現在「預約留言」頁 | P1 |
| C2 | 預約規則一致 | 和 LINE 預約相同：明天起 14 天內、09–18 整點、**週日公休不列**（兩邊 2026-10-21 一起改） | P1 ✅ |
| C3 | 客戶比對 | 手機號碼**剛好對到一位**客戶時，提示店員「可能是 ○○○」，由店員確認後才掛上。**不自動掛**，因為官網任何人都能填別人的手機 | P1 |
| C4 | 新預約通知店員 | y1crm 選單顯示紅點和未處理數 | P1 |
| C5 | 防灌水 | 同一個 IP 和同一支電話有次數限制、隱藏欄位擋機器人、欄位長度上限 | P1 |
| C6 | 一般詢問表單 | 「聯絡我們」的留言也進 y1crm（新的「官網留言」清單或併入預約留言），見討論事項 | P1 |

### E. 非功能需求

| 編號 | 項目 | 要求 |
|---|---|---|
| E1 | 服務 | 本機 port **8006**，systemd 服務 `y1web`，開機自動啟動、掛掉自動重啟 |
| E2 | 手機優先 | 主要客群是長輩和家屬：字級 18px 起、按鈕夠大、對比夠高；390px 寬度不能出現橫向捲動。頁首有「字放大」與「深色／淺色」開關（John 2026-10-21 要求，都用圖示表現） |
| E3 | 速度 | 首頁傳輸量 300KB 以內（不含地圖），不用前端框架，在 4G 上 3 秒內可閱讀 |
| E4 | SEO | 伺服器端產生 HTML；sitemap.xml、robots.txt、每頁標題和描述、社群分享預覽圖、店家結構化資料（地址、電話、營業時間）；網址用英文代稱，避免分享到 LINE 時變成一長串編碼 |
| E5 | 個資 | 表單有同意勾選、隱私權政策；個資只存在本機資料庫，不送第三方表單服務；記錄檔不寫完整手機號碼 |
| E6 | 安全 | 公開網站的資料庫帳號**碰不到客戶資料表**；只用 HTTPS；安全標頭；輸入驗證 |
| E7 | 可維護 | 和 y1crm 同一套技術（FastAPI＋Jinja2）；內容由店員在後台改，不用改程式 |
| E8 | 日期 | 畫面用民國年，程式與資料庫用西元，沿用 y1crm 的 DF 慣例 |
| E9 | 測試 | 單元測試（表單驗證、預約串接、LINE 預約碼）；瀏覽器在 1280、800、390 三種寬度截圖檢查；上線前用手機 4G 實測 |
