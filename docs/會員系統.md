# 會員系統（設計草案 v0.1）

> 2026-10-29。John：「我想依序做（每日聽練的改進），但是要先設計會員系統。Google 和 LINE 綁定客戶資料共用，我需要提供些什麼。」
> 相關：[每日聽練](每日聽練.md)、[討論事項](討論事項.md) 9h、[Facebook 串接](Facebook串接.md)。

## 1. 目標

- 客人用 **Google 或 LINE 登入**，不設密碼；同一個人可以兩種都綁在同一個會員。
- 會員可以**連結到 CRM 的客戶資料**：
  - 店員在客戶明細看得到這位客人是會員、每日聽練的完整紀錄（John 11-02：盡可能看見所有練習細節）；
  - 客人在官網、每日聽練看得到自己的資料（範圍見 D1）。
- 每日聽練：沒登入照舊存在瀏覽器；登入後存到伺服器，換手機、多台裝置都同步。
  這會取代原本「存在使用者自己的 Google 雲端硬碟」的計畫：Google 只要基本登入權限，不用申請雲端硬碟權限。
- 以後做 app 用同一套後端，資料格式不變。

## 2. 架構

### 2.1 資料放哪裡

新開一個資料庫 `y1member`，不放進 `crm1`，CRM 的客戶表不改欄位：

| 表 | 內容 |
|---|---|
| `members` | 會員編號、稱呼、`customer_id`（沒連結＝NULL；一位客人只能連一個會員）、連結方式與時間、同意時間、建立與最後登入時間、停用。不存頭像：用不到，官網 CSP 也不載外部圖片 |
| `member_identities` | 會員、`provider`（google／line）、`subject`（Google sub／LINE userId）、Email（只有 Google）、綁定時間；`(provider, subject)` 唯一 |
| `member_sessions` | 登入憑證的雜湊、會員、到期時間、裝置說明 |
| `member_progress` | 會員、程式（`practice`）、資料 JSON、更新時間 |
| `link_codes` | 店內綁定碼：客戶、碼的雜湊、到期時間、使用時間、產生的店員 |
| `link_requests` | 線上申請連結：會員、填的稱呼與電話、狀態、處理的店員 |

新表一律用 `utf8mb4_unicode_ci`，跟 `customers` 一樣，JOIN 才不會出錯。

### 2.2 誰能讀什麼

- **官網（`y1web_app`）**：
  - `y1member` 只給資料列的讀寫（`scripts/setup_db.py` 的 `MEMBER_GRANTS`）：不能建表、改表；`link_codes` 只能標記用掉；
  - 客戶資料**只能透過檢視表** `crm1.v_member_customer` 讀。目前只有三欄：客戶編號、稱呼（姓＋先生／女士）、LINE userId 的 SHA-256。
    LINE userId 本身也不給，官網拿登入得到的 userId 算雜湊來比對。D1 的預約、保養提醒做到時再加檢視表。
  - 檢視表用 `ALGORITHM=TEMPTABLE`，而且只給 SELECT：DEFINER 檢視表如果可以更新，會用建立者的權限寫進 `crm1.customers`。
  - 身分證、生日、地址、電話、聽力檢查檔案、備註**永遠不開放**。資料庫限制欄位，所以就算官網被入侵也讀不到這些。
  - 「只能看自己那一筆」是靠程式判斷，不是資料庫限制。所以開放的欄位要越少越好。
  - 這會改變目前「官網不讀客戶資料」的原則，見 D6。
- **CRM（y1crm）**：
  - 客戶明細顯示會員徽章（Google／LINE）和每日聽練紀錄（每天回數、時間，各項題數／答對／等級）；
  - 有「產生綁定碼」按鈕和「會員連結申請」清單；
  - 可以解除連結。

### 2.3 登入流程

- 在伺服器端走 OAuth 授權碼流程，加上 PKCE、state 和 nonce，並驗證 id_token。Google 用公開金鑰驗，LINE 用 `/oauth2/v2.1/verify`。
- 不載入 Google 或 LINE 的網頁程式，只做頁面轉址，所以官網的 CSP 不用放行外部程式。
- 權限只要最基本的：Google `openid email profile`，LINE `openid profile`。不要 LINE 的 Email，因為要另外申請，我們也用不到。
- 登入憑證：
  - 網頁用 HttpOnly、Secure、SameSite=Lax 的 cookie，伺服器只存雜湊；
  - app 拿同一種憑證，放在 Authorization 標頭。
- **Google 和 LINE 可以都綁，不是擇一**（2026-10-31 John 問）：
  - 用其中一種登入以後，到「帳號設定」按「也用 LINE 登入」或「也用 Google 登入」，就能綁第二種。之後兩種都能登入同一個會員；
  - 要綁的那個帳號如果已經是另一個會員，就把兩個會員**合併**，練習紀錄用 `merge()` 合在一起；
  - 兩個會員分別連到**不同客人**時不合併，請客人洽門市；
  - 會員至少要留一種登入方式，最後一種不能解除；
  - 沒登入時，第一次用另一種方式登入會開出一個新會員，所以登入頁要提醒「用過另一種方式登入的，請先用那一種登入，再到帳號設定綁定」。
- **不用 Email 自動合併帳號**：LINE 拿不到 Email，用 Email 比對也容易被冒用。

### 2.4 會員怎麼連到客戶資料

- **LINE 自動連結**：LINE Login channel 必須和現在的官方帳號（Messaging API channel 2010707786）放在**同一個 Provider**。這樣登入拿到的 userId 才會和 `customers.line_user_id` 一樣，已經綁 LINE 的客人登入後就自動連上。2026-10-29 時，71 位客人裡有 3 位綁了 LINE。
- **其他客人不能只靠輸入手機號碼連結**，因為知道號碼的人就能看到別人的資料。有兩種做法：
  1. **店內綁定碼**：店員在 CRM 客戶明細按「產生綁定碼」，客人用手機掃 QR Code 或輸入 6 碼，10 分鐘內有效，只能用一次。
  2. **線上申請**：客人在官網按「我是門市客人」，填稱呼和手機，CRM 會出現申請，店員確認是本人才連上。
- 連結時客人要勾選個資告知同意，CRM 會記下同意時間。
- 客人可以自己解除連結或刪除會員。刪除會員時，登入方式、練習紀錄、登入憑證一起刪掉；CRM 的客戶資料照原本的規則保存。

### 2.5 每日聽練怎麼接

- 沒登入：照舊存在瀏覽器，也照舊可以用備份碼。
- 登入後：
  - 開啟時和練完時呼叫 `GET`／`PUT /api/member/progress/practice`；
  - 伺服器和瀏覽器的資料都用同一個 `merge()` 合併，順序不影響結果，重複合併也不會變；
  - 沒網路時先存本機，有網路再同步。
- 伺服器要再用 `clean()` 檢查一次資料，並限制大小。

## 5. 做的順序

3. 回到每日聽練的改進，照順序做：小改 → 進度頁 → 華語語音題。

## 6. 以後做 app

- 後端和登入憑證共用，app 端改用 Google 和 LINE 的原生登入套件，換到我們的登入憑證。
- **iPhone 上架**：有 Google 或 LINE 登入時，Apple 規定還要提供一種同等的登入方式，通常是「用 Apple 登入」。這需要 Apple 開發者帳號，每年 US$99。Android 沒有這個規定。
