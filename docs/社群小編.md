# 社群小編（設計 v0.2：第一步「每日貼文草稿」已上線）

> 2026-11-01。John 參考 [Clara Social](https://clarasocial.com)：「我們較多的是使用情境，不做單品廣告。用原有 PO 文和新的『手動』PO 文建立圖文，
> 不求電影品質，只要有流暢的吉普力卡通和自然的對話。IG 和 TikTok 後續會申請建立。」
> 相關：[Facebook 串接](Facebook串接.md)、[討論事項](討論事項.md) 9i。

## 1. 要做的

- 素材：粉專**原有貼文**（2026-11-01 有 62 篇，2022–2026，照片約 104 張、影片 4 支）和店員**手動寫的新貼文**。
- 產出：
  1. **圖文**：溫暖手繪動畫風的插圖，加上對話框和文字，可以是單張、多張輪播或四格漫畫；
  2. **短影音**：插圖動起來，加上角色對話的配音和字幕，15–30 秒。
- 內容是**使用情境**（家人對話、到店、保養、生活小技巧），不做單品廣告。
- 發到 FB 粉專；IG、TikTok 帳號開好、審查通過後再接。
- **每則都要店員按「發佈」才會送出**，不做 Clara 那種全自動發文（見第 4 節）。

## 2. 流程（CRM 裡的一頁）

1. 選一篇原有貼文，或手動寫一段 → 本機 AI 改寫成**情境腳本**：角色、場景、每格畫面、2–4 句對話 → 店員修改。
2. 每格產生 2–3 張插圖讓店員挑，不滿意就重畫。
3. **中文字由程式排版加上去**（對話框、標題、店名），不讓 AI 畫字：AI 畫中文常常寫錯。
4. 圖文輸出 → 店員審核 → 排程發到 FB。
5. 影片：每格插圖做成 4–5 秒動畫 → 配上對話語音、字幕、背景音樂 → 接成一支 → 店員審核 → 發 FB Reels。

## 3. 技術

- 全部在本機跑，不送雲端。原有貼文的照片和留言可能有客人。
- **固定角色**：設計幾位虛構角色（例如阿公、阿嬤、女兒、孫子、驗配師），做成角色設定圖，每次都照這個畫，同一個角色才會長得一樣。這是插圖最難調的地方。
- **不把客人的照片轉成卡通**：卡通化以後還是認得出來，一樣要本人同意。只參考沒有人的照片，例如店內、街景。
- **風格**：吉卜力那種溫暖、水彩、手繪的感覺。不用吉卜力的名字和角色，也不用拿吉卜力電影畫面訓練出來的模型。
- **顯卡**：
  - 現在兩張 V100 都被常駐模型占掉約 23GB／32GB，空出來的大約 9GB 只夠畫插圖，不夠做影片。
  - 573 那張（只能跑文字）負責 24 小時的 LINE 客服，而且跑影像會當掉，不用它。
  - **影片可以趁晚上借 0002 那張**：晚上沒人用 OCR，先卸下 OCR 模型、整張拿來做影片，早上再裝回去。
  - 第 3 張卡修好以後，就專門給這裡用。
  - V100 比較舊，不支援新的加速方式，一段 5 秒的動畫可能要十幾到幾十分鐘，要實測。所以影片在晚上排程批次做。
- **對話文字**：本機 `qwen3:32b`。
- **配音**：
  - 可以先用聽損模擬用過的 edge-tts 台灣聲音（曉臻等），但比較像朗讀；
  - 要像真人對話，得試本機的台灣腔模型。如果要模仿某個人的聲音，要那個人同意並錄樣本；
  - 也可以由店員自己錄。
- **發文**：
  - FB 的權杖已經有發文權限，要加上排程和影片上傳；
  - 要看觸及等數字，得多勾 `read_insights`；
  - IG 要開專業帳號連到粉專，申請 `instagram_content_publish` 並通過審查；
  - TikTok 要另外申請 Content Posting API 並通過審核，沒審過只能發成「私人」。

## 4. 法規與用語

- 助聽器是醫療器材，醫療器材廣告刊播前要先申請核准。純衛教、生活情境比較不像廣告，但**情境對話很容易寫出「戴了之後聽得好清楚」這種效果描述**，這正是要避開的。
- 腳本和文案都要先經過現有的用語檢查（價格、療效、最高級、使用前後對比），也不寫品牌、型號，最後由店員審核。
- 社群貼文算不算廣告，請問衛生局或顧問（和「法規用語」同一件事）。
- 背景音樂只用有授權可以商用的。

## 5. 做的順序

1. **試做**（還沒做，要 John 同意）：挑一篇原有貼文 → 腳本 → 4 格插圖 → 一支約 15 秒、有配音的影片，先看風格、角色和聲音能不能接受。
   - 要安裝 PyTorch 和下載模型，約 30–60GB，放 `/mnt/raid1`；
   - 試影片的晚上，OCR 會暫停。
2. 試做可以接受，再做 CRM 頁面：腳本 → 插圖 → 圖文 → 排程發 FB。
3. 加短影音和夜間批次處理。
4. IG、TikTok 審查通過後再接上。

### 6.2 做了什麼
- **程式**：y1crm
  - `api/fb_drafts.py`；
  - 資料表 `fb_post_drafts`，DDL 在 `scripts/schema_fb.py`；
  - 頁面「官網 → 粉專貼文」（`/fb-posts`，權限 web＝admin、manager）；
  - 設定 `[social]`：`draft_enabled`、`draft_hour`（7）、`draft_count`（3）、`news`。
- **每天 06:00 後**：本機 `qwen3:32b`（573 那張卡，純文字）寫 3 則，每則約 5–20 秒。挑題目的優先順序：
  1. 節日（前 3 天起）；
  2. 時事新聞；
  3. 題庫，四類輪流：保養小教室、家人溝通、聽力保健、互動提問；
  4. 官網文章（還沒分享過的專欄、小教室）；沒有的話改介紹官網工具；
  5. 其他題庫類別。
- **新聞來源**（RSS）：中央社「生活醫藥」、衛福部焦點新聞、疾管署、自由時報「生活」、ETtoday「健康」、公視、鏡週刊、Yahoo 新聞「健康」、Heho 健康、關鍵評論網（11-09 John「其他媒體也找找，不要每天都自由時報的」加了後面 6 家）。
  - 不要每天同一家：最近 7 天用過的媒體，每用過一次扣 5 分；同一家要明顯比別家相關（例如標題有「聽力」）才會再選到；
  - 用關鍵字打分數：聽力、耳朵、失智、長輩、寒流、流感……；
  - 擋掉的題材：災難、犯罪、政治、博弈；
  - 只用最近 3 天的新聞；
  - AI 只拿標題和摘要來寫，發文時附原文連結。
- **不重複**：用過的題目、新聞、官網文章，60 天內不再出。按「不要」的也算用過。
- **每篇固定附加的官網宣傳**（程式加，不讓 AI 寫）：「—— 韻譯助聽器・官網 ——」，下面是每日聽練、線上聽力測驗、線上預約三行連結，放在本文和 hashtag 之間。
- **管理者的操作**：
  - 勾選要發的貼文；
  - 可以直接改字和連結，改完自動存；
  - 「換一則」讓 AI 重寫，「不要」丟掉這則；
  - 「多寫一則」可以指定類別，或自己出題；
  - 按「發佈勾選的」並確認，才會送到粉專。
- **擋與提醒**：
  - 會擋下不能發的：提到價格，或還有【…填寫】待填的地方（節日貼文的營業時間要店員自己填）；
  - 會提醒、但確認後可以發的：療效或最高級用語、免費／贈品／抽獎、品牌、寫成「耳機」。
- **提示詞的規則**：
  - 不提價格、療效、品牌；
  - 不編造客人故事；
  - 不做診斷；
  - 身體不適要就醫（11-09 John 要求加）：寫到身體不舒服一律請讀者看醫師或問醫師、藥師，不自己推測什麼事會引起什麼症狀；「歡迎來電或到門市」只接在聽力、助聽器的問題後面；
  - 時事和聽力的連結只從生活面切入（陪長輩出門、和醫護或家人溝通、助聽器的日常照顧）；
  - 保養做法只能用 LINE 客服知識庫裡有的。
- **試寫時 AI 犯過的錯**：
  - 把助聽器叫成「耳機」；
  - 自己編出「出門前關機」這種錯誤建議；
  - 11-09 時事（公費疫苗）寫成「接種後如有不適……歡迎來電或到門市」——身體不適導到助聽器門市，用語檢查抓不到。
    加規則時也發現：規則裡舉的症狀例子（耳痛、頭暈……）會被 AI 照抄進貼文，硬把疫苗和耳朵症狀扯在一起；
    叫它「不要扯在一起」反而更常扯。有效的是正面告訴它從哪裡切入（上一點），規則裡不舉症狀。

  提示詞已經加強，也加了提醒，但**一定要人看過才能發**。

### 6.3 自動發佈、同步到聽力專欄、SEO 關鍵字（2026-11-08 下午）

**自動發佈**
- 設定在 `[social]`：`draft_hour = 6`、`auto_publish = "10:30"`。`auto_publish` 留空就是不自動發。
- 每日草稿預設勾選，勾選狀態存在資料表 `fb_post_drafts.picked`，取消勾選會馬上存。
- 10:30 時自動發的草稿要同時符合：
  - 當天的每日草稿；
  - 還勾著；
  - 沒有紅色錯誤，也沒有黃色提醒；
  - 至少在 09:30 前就寫好（`AUTO_REVIEW_MIN = 60`），留時間給門市看。
- 不會自動發的，畫面上會寫原因：管理者按「多寫一則」的、有提醒的、太晚才寫好的。
- 主機停機錯過 10:30 的話，當天 21 點前開機會補發。
- 寫稿時遇到提醒（例如把助聽器寫成「耳機」），會請模型改掉再寫，最多 3 次，留提醒最少的那一版，讓更多草稿可以自動發。
- 2026-11-08 加欄位之前寫的草稿一律 `picked = 0`，不會被自動發。

**同步到聽力專欄**
- 每則草稿多存三個欄位：
  - `seo`：官網標題、摘要、專欄分類、搜尋關鍵字、網址代稱；
  - `web_sync`：要不要同步；
  - `web_article_id`：同步後的專欄文章。
- `seo` 由本機 AI 先擬好（`seo_meta`），程式再清理一次：去掉價格、療效、品牌、促銷字眼，每篇都補上「台北助聽器」「中正區助聽器」。
- 管理者可以展開修改。這些類別預設同步：保養、聽力保健、家人溝通、時事、自己出題。互動提問、節日、官網文章介紹、官網工具預設不同步。
- 發到粉專成功後，會在專欄發一篇：
  - 內文是粉專本文，拿掉官網宣傳和 hashtag，「・」改成清單；
  - 新聞類附「資料來源」連結；
  - 網址代稱撞到時，自動加 -2。
- 發佈前會先用專欄的規則檢查欄位；不合格的會變成紅色錯誤，避免粉專發出去了、專欄卻存不進去。

**SEO**
- 官網管理的聽力專欄、使用小教室多了「搜尋關鍵字」欄位（`extra.keywords`，最多 10 個，不收價格和療效用語）。
- 既有的 6 篇專欄和 8 篇小教室，關鍵字由本機 AI 擬、人工刪改後補上（`updated_by = seo-keywords`）。
- 官網的改動：
  - 每頁都有 meta keywords（全站關鍵字＋該頁關鍵字）、canonical、og:url；og:image 改成完整網址（原本是相對路徑，Facebook 抓不到）。
  - 門市的結構化資料多了網址、地區、keywords、sameAs（Google 地圖、Facebook）。
  - 專欄、小教室有 Article 結構化資料；sitemap 加上 lastmod。
  - 專欄頁有搜尋框（`/column?q=`，結果頁 noindex），下面列常見關鍵字。
  - 專欄文章最下面列出關鍵字，點了就搜尋；地區詞不列。
- 全站共通的關鍵字在 `content.SITE_KEYWORDS`：助聽器、台北助聽器、中正區助聽器、古亭站、中正紀念堂、助聽器保養、聽力檢查、助聽器補助、助聽器驗配。
- Google 早就不看 meta keywords。實際有用的是標題、摘要、內文、結構化資料和站內連結，所以關鍵字也放進這幾個地方。

### 6.5 文章短影音（2026-11-08 試做，John「聽力專欄找一則來做個影片看看，直接在網站上看效果」）

- **⚠ 11-08 踩過的坑（John 回報「開頭全黑 20 秒、影像字幕時間軸錯亂」）**：
  1. 各段分別編碼成 H.264＋AAC 再 `-c copy` 接起來：有些瀏覽器的硬體解碼會前段黑屏、聲音畫面對不上；顏色還是 JPEG 的全範圍 yuvj420p。→ 各段只做高畫質暫存畫面、聲音存無壓縮 WAV，最後**整支一次編碼**（yuv420p tv 範圍、bt709、固定 30fps、每 2 秒一個關鍵格）。
  2. 聲音照取樣點裁切時沒先轉取樣率：edge-tts 的 mp3 是 24kHz，`atrim=end_sample` 照 24kHz 算，每段聲音變 1.84 倍長、越後面差越多。→ 先 `aresample=44100` 再裁。
  3. 語音檔本身前後帶靜音，段尾空 1.4 秒很拖 → 先裁掉，留白由 LEAD 0.35／TAIL 0.65 秒控制。
  - 檢查方法：每段量旁白開始時間（音量 > 峰值 8%）要都在段頭 +0.4 秒左右；瀏覽器要**從第 0 秒**播放檢查，不能只跳到中間。
